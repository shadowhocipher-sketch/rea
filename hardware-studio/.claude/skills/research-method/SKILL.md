# 研究方法

目的：写进能力库的每一条事实，以后的人都能顺着链接核对，而且知道它有多可靠。

## 1. 来源分级

| 级别 | 来源 | 例子 | 用法 |
|---|---|---|---|
| **S** | 原厂一手资料 | 原厂数据手册、技术参考手册、硬件设计指南、原厂勘误；标准原文；政府或监管机构的法规原文 | 参数和法规条款**必须**来自 S 级 |
| **A** | 官方二手资料 | 原厂应用笔记、官方 FAQ、官方 GitHub 仓库、认证机构（CNCA、FCC、欧盟委员会）发布的指南 | 可以单独作为依据，但参数要优先回到 S 级核对 |
| **B** | 分销商和制造平台 | 立创商城、JLCPCB、DigiKey、Mouser、LCSC 的商品页 | **价格和库存的唯一可信来源**；商品页上的参数要回到 S 级核对 |
| **C** | 社区和第三方 | 博客、论坛、教程、开源项目的 README、AI 生成的内容 | 只能当线索，不能单独作为事实依据 |

## 2. 交叉核实

- **参数**：从 S 级数据手册里读取，引用到章节或表格。B 级和 S 级冲突时以 S 级为准，并把冲突记下来。
- **模块（开发板、屏幕模组）**：模块没有统一的数据手册。分清"芯片参数"（引用芯片数据手册）和"模块参数"（引用卖家页面，标 B 级，注明"不同卖家可能不同"）。
- **法规**：引用法规原文的编号和条款，再附一个官方的解读页面。两者对不上，或只有第三方文章时，标"待核实"。
- **价格**：至少看一个 B 级来源；有阶梯价时记录所有档位。

## 3. 引用格式

参数：

```markdown
| 工作电压 | 3.0–3.6 V | [ESP32-S3 数据手册 v2.0，表 5-2](https://...) · S · 2026-11-01 |
```

价格：

```markdown
| 型号 | 数量档 | 单价 | 来源 | 日期 |
| ESP32-S3-WROOM-1-N16R8 | 1 / 10 / 100 | ¥xx / ¥xx / ¥xx | [立创商城 Cxxxxxx](https://...) | 2026-11-01 |
```

法规：

```markdown
- 要求：…… 依据：[法规名称和编号，条款](官方原文链接) · S · 2026-11-01
```

每条都要有：**链接**、**来源级别**、**查询日期**。

## 4. 必须用的标记

| 标记 | 什么时候用 | 还要写什么 |
|---|---|---|
| **未查到** | 找过但没找到可信来源 | 查过哪些地方 |
| **估算** | 没有直接数据，由其他数据推算 | 推算依据和公式；例如"按同类器件立创价格 ¥x–y 取中值" |
| **待核实** | 只有 C 级来源，或者来源之间有冲突，或者理解没把握 | 已有的线索和冲突点 |
| **未运行** | 代码、电路或流程没有在实物或工具上跑过 | 计划怎么验证 |

不用的写法："一般是""大约""通常为"后面不跟来源。

## 5. 网络受限时

1. 先试官方站点（WebFetch）；被拦截或打不开，就记下 URL 和错误信息；
2. 再用搜索（WebSearch）找同一份文件的官方镜像或其他官方页面；
3. 都不行，就写"未查到（原因：访问 xxx 时出现 yyy）"。不要退回到凭记忆写。

## 6. 检查清单（写完自己检查）

- [ ] 每条参数、价格、法规都有链接、级别、日期；
- [ ] 价格都来自 B 级来源，或者标了"估算"；
- [ ] 没有只靠 C 级来源的事实（有的话已经标"待核实"）；
- [ ] 模块参数和芯片参数分开写了；
- [ ] 没有"一般""大约"之类不带来源的说法。

`evals/` 里有检查脚本，会扫描 `knowledge/`、`mfg/`、`compliance/` 下的表格，找出缺少链接或日期的行。
